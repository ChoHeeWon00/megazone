# STEP 10. TEST-PLAN.md — "다 됐는지" 확인하는 시험지 (PLAN P-09)

> **TEST-PLAN.md** = 앱을 만들기 **전에** 써 두는 **시험 문제와 정답**
> 실제로 시험 본 **결과**는 PLAN.md에 적어요.

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| PRD.md | 5. Must, 6. 인수 조건 | **정답의 출처**예요. Must마다 시험 문제가 하나 이상 있어야 해요. |

## ❓ 왜 만들기 "전에" 써야 할까?

| 만든 다음에 정답을 정하면 | 만들기 전에 정답을 정하면 |
|---|---|
| "음… 이 정도면 된 것 같은데?" | 정답과 비교해서 맞다/틀리다를 정확히 |
| AI가 만든 결과에 맞춰 정답을 바꾸게 됨 | 원래 원한 것을 지킬 수 있음 |
| 사람마다 판단이 다름 | 누가 봐도 같은 판단 |

### ⭐ 정답은 "눈으로 볼 수 있는 문장"으로

| ❌ 나쁜 정답 | ✅ 좋은 정답 |
|---|---|
| 등록이 잘 된다 | "할 일" 칸에 내가 쓴 제목의 카드가 보인다 |
| 오류 처리가 된다 | 저장되지 않고 입력 칸 아래에 이유가 보인다 |
| 데이터가 유지된다 | 새로고침해도 같은 카드가 같은 칸에 있다 |

### 10-0. PLAN에 시작 표시

### 대화 1. 시험 문제 뽑기

- claude-code 입력
```claude-code
PRD.md의 Must와 인수 조건, SCREEN-SPEC, API-SPEC, DATA-MODEL, DECISIONS를 읽으세요.
TEST-PLAN.md에 넣을 검사 시나리오를 만들어 주세요.
칸: 시나리오(T-01부터 번호) / 시작 조건과 입력 / 행동 / 기대 결과 / 관련 요구와 설계
- 기대 결과는 화면에서 눈으로 볼 수 있는 문장으로 쓰세요. "정상", "잘 된다" 같은 말은 쓰지 마세요.
- 정상, 잘못된 입력(빈 제목, 띄어쓰기만), 빈 보드, 상태 되돌리기(D-002), 삭제 취소·확인, 저장 실패, 새로고침과 서버 재시작 뒤 유지를 모두 포함하세요.
- 화면을 거치지 않고 서버에 직접 보낸 잘못된 요청도 거절되는지 시나리오를 넣으세요.
대화에 먼저 보여 주세요.
```

### 대화 2. 직접 정답 고쳐 보기

AI가 쓴 정답 중 **흐릿한 문장**을 찾아 고쳐 보세요.

| AI가 쓴 기대 결과 | 내가 고친 문장 |
|---|---|
| 상태 변경이 정상 동작한다 | |
| 삭제가 잘 된다 | |
| 연결 실패를 처리한다 | |

<details>
<summary>👀 예시 답 보기</summary>

| AI | 고친 문장 |
|---|---|
| 상태 변경이 정상 동작한다 | 카드가 "진행 중" 칸으로 옮겨진다 |

| 연결 실패를 처리한다 | "저장하지 못했어요" 안내가 보이고, 쓴 내용이 입력 칸에 남아 있다 |

### 대화 3. 빠진 문제 찾기

- claude-code 입력
```claude-code
작성한 시나리오가 PRD의 Must와 인수 조건, SCREEN-SPEC의 빈 결과·처리 중·오류 상태를 모두 다루는지 확인하세요.
빠진 것이 있으면 목록으로 알려 주세요. 파일은 아직 고치지 마세요.
```

- [ ] Must 기능마다 시나리오가 하나 이상 있나요?
- [ ] 잘못된 입력과 실패 시나리오가 있나요?
- [ ] "새로고침해도 남아 있다"와 "서버를 껐다 켜도 남아 있다"가 있나요?
- [ ] 버튼·안내 **글자가 올바른지** 보는 항목이 있나요? (예: "완료**으로**" 같은 틀린 글자)

- claude-code 입력
```claude-code
빠진 시나리오를 추가해서 TEST-PLAN.md로 저장하세요. 맨 위 상태는 "작성 중"으로 두세요.
```

내가 읽고 확인한 뒤:

- claude-code 입력
```claude-code
TEST-PLAN.md를 확인했습니다. 맨 위 상태를 "확정"으로 바꾸세요.
```

### ⭐ 코드를 만들기 전 마지막 점검: 문서끼리 같은 말을 하나?

- claude-code 입력
```claude-code

특히 필드 이름, 상태 값, 빈 제목 규칙, 되돌리기(D-002), 저장 실패 처리를 비교하세요.
```
