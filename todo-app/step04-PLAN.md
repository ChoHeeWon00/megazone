# STEP 4. PLAN.md — "작업 계획판" 만들기

> **PLAN.md** = 결정을 따라 **지금 하는 작업**: 할 일, 상태, 확인 결과, 다음 행동
> 지난 일만 적는 일기가 아니라, **앞으로 할 일**도 함께 적는 계획판이에요.

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| DECISIONS.md | D-001 (할 일 카드 웹앱, AI 기능 없음) | 계획은 **확정한 결정을 근거로** 세워요. 결정이 없으면 무엇을 할지 정할 수 없어요. |
| AGENTS.md | "실행하지 않은 검사는 미실행", "결정은 사람이" | **상태 규칙**("확인 대기"와 "완료"의 구분)의 근거예요. |
| README.md | 현재 상태 | 지금 어디까지 왔는지 **출발점**을 확인해요. |

## 🔗 이 파일을 나중에 참고하는 곳

| 파일·단계 | 무엇을 가져가나 |
|---|---|
| **STEP 5~12 전부** | 시작할 때 "P-번호 진행 중", 끝날 때 "확인 대기 → 완료" |
| STEP 11 (코드 만들기) | "구현 인계" 칸 = AI에게 주는 작업 지시서 |
| 모든 새 대화의 AI | "어디까지 했고 다음은 뭐야?" |

---

## 🧸 쉽게 말하면

PLAN은 **숙제 체크리스트**예요.

```
📒 숙제 체크리스트
  ☑ 국어 받아쓰기 (엄마가 확인함)     ← 내가 확인한 것만 체크!
  □ 수학 문제집 3쪽 (끝 = 채점까지)   ← 할 일 + 끝나는 기준
  
  막힌 것: 준비물 가게가 문 닫음
  내일 할 일: 과학 준비물 챙기기
```

---

## ❓ 왜 필요할까?

내일 새 대화를 열면 AI는 묻습니다. **"어디까지 했어요?"**

| PLAN이 없으면 | PLAN이 있으면 |
|---|---|
| 어제 한 일을 다시 설명해야 함 | 파일을 읽고 바로 이어서 함 |
| AI가 "완료했어요"라고 한 걸 진짜 완료로 착각 | "확인 대기"와 "완료"를 구분 |
| 어디서 멈춰야 끝인지 모름 | 작업마다 **완료 조건**이 있음 |
| 다음에 뭘 할지 헷갈림 | "다음 행동"이 한 줄로 적혀 있음 |

### ⭐ 가장 중요한 규칙: 상태는 5가지만

| 상태 | 뜻 | 예 |
|---|---|---|
| **예정** | 아직 시작 안 함 | 화면 설계 |
| **진행 중** | 하고 있음 | PRD 작성 |
| **확인 대기** | AI가 "다 했어요"라고 했지만 **내가 아직 확인 안 함** | PRD 저장 |
| **완료** | **내가 직접 확인함** | README 확인 끝 |
| **막힘** | 문제가 있어 멈춤 | 설치 권한 없음 |

> ⚠️ **AI가 "완료했습니다"라고 해도 → "확인 대기"**
> 내가 파일을 열어 보거나 실행해 본 뒤에만 → **"완료"**

### PLAN에 쓰지 않는 것

| 이런 내용은 | 여기에 |
|---|---|
| 왜 그렇게 정했는지 (이유) | DECISIONS |
| AI가 멈추고 물어야 할 조건 | AGENTS (이미 있음) |
| 무엇을 만들지 (기능) | PRD |
| 지난 계획의 변경 이력 | Git 커밋 기록 |

## 🗣️ AI와 대화하며 만들기

### 대화 1. 이어받는 사람이 궁금한 것 물어보기

- claude-code 입력
```claude-code
README.md, AGENTS.md, DECISIONS.md를 읽으세요. 이제 PLAN.md를 만들려고 합니다.
이 파일은 내일 새 대화에서 작업을 이어받는 AI와 제가 읽습니다.
이어받는 사람이 일을 시작하기 전에 꼭 알아야 할 질문을 4~5개 알려 주세요.
아직 파일은 만들지 마세요.
```

**AI 대답 예시**
> 1. 지금 어디까지 했고, 다음에 할 일은 정확히 무엇인가?
> 2. 각 단계는 무엇이 되면 "끝"인가?
> 3. 이 계획의 근거는 무엇이고, 아직 정하지 않은 것은 무엇인가?
> 4. 이번 범위에서 하지 않는 일은 무엇인가?
> 5. 막히면 어떻게 하나?

### 대화 2. 질문을 "칸 이름"으로 바꾸기

| 질문 | 내가 붙인 칸 이름 |
|---|---|
| 이번에 무엇을 끝내고 무엇은 안 하나? 근거는? | |
| 해야 할 작업, 끝나는 기준, 지금 상태는? | |
| 실제로 확인한 결과는? | |
| 막힌 것, 아직 정하지 않은 것, 다음에 할 일은? | |

<details>
<summary>👀 예시 답 보기</summary>

| 질문 | 칸 이름 |
|---|---|
| 이번에 무엇을 끝내고 무엇은 안 하나? 근거는? | `## 이번 목표와 범위` |
| 해야 할 작업, 끝나는 기준, 지금 상태는? | `## 작업 목록` (번호·작업·**완료 조건**·상태) |
| 실제로 확인한 결과는? | `## 실제 검증 결과` |
| 막힌 것, 아직 정하지 않은 것, 다음에 할 일은? | `## 남은 문제와 다음 행동` |

- "막히면 멈추고 묻는다" 같은 **규칙**은 AGENTS에 이미 있으니 PLAN에 다시 쓰지 않아요.
- AI가 **"실제 검증 결과"를 빠뜨리는 경우가 많아요.** "완료 조건"(기준)과 "실제로 본 것"(결과)은 다른 칸이에요.

</details>

### 대화 3. 첫 계획 받기

이번 목표는 **"무엇을, 어떻게 만들지 문서로 정하기"**예요. 아직 코드는 없어요.

- claude-code 입력
```claude-code
PLAN.md를 아래 칸으로 만들려고 합니다.
- 이번 목표와 범위 / 작업 목록 / 실제 검증 결과 / 남은 문제와 다음 행동
이번 목표는 "무엇을, 어떻게 만들지 문서로 정하기"입니다. 코드 작성과 설치는 이번 범위가 아닙니다.
참고할 문서는 README, AGENTS, DECISIONS(D-001)입니다. 아직 없는 파일은 없다고 적으세요.
작업 목록은 고유 번호 P-xx로 아래 순서대로 넣고, 작업마다 눈으로 확인할 수 있는 완료 조건을 적으세요.
- P-01 README, P-02 AGENTS, P-03 DECISIONS D-001: 제가 확인했으므로 "완료"
- P-04 PRD, P-05 ARCHITECTURE, P-06 SCREEN-SPEC, P-07 DATA-MODEL, P-08 API-SPEC, P-09 TEST-PLAN: "예정"
실제 검증 결과에는 제가 확인한 것만 쓰세요.
- README, DECISIONS: 파일을 열어 내용을 확인함
- AGENTS: 새 대화에서 AI가 규칙을 설명하고, 없는 파일은 없다고 말함
사용할 기술이나 저장 방식처럼 아직 정하지 않은 것은 정하지 말고 "남은 문제와 다음 행동"에 적으세요.
초안을 대화에만 보여 주세요.
```

**이 문장을 넣는 이유**

| 문장 | 이유 |
|---|---|
| "작업마다 완료 조건" | 어디서 멈춰야 끝인지 알게 |
| "제가 확인했으므로 완료" | **내가 확인한 것만** 완료 |
| "실제 검증 결과에는 제가 확인한 것만" | AI가 확인 방법을 지어내지 않게 |
| "아직 정하지 않은 것은 정하지 말고" | 기술·저장 방식을 AI가 혼자 정하지 않게 |

> 💡 STEP 2의 새 대화 시험을 **안 했다면** "AGENTS: 미확인", 상태는 "확인 대기"로 바꿔서 입력하세요. 안 한 확인을 했다고 적으면 안 돼요.

**AI 대답 예시**

```markdown
# 작업 계획

## 이번 목표와 범위
- 완료할 목표: 무엇을, 어떻게 만들지 문서로 정하기
- 이번에 하지 않을 일: 코드 작성, 프로그램 설치
- 참고할 문서: README.md, AGENTS.md, DECISIONS.md (D-001)
- 아직 없는 문서: PRD.md 이후 설계 문서

## 작업 목록
| 번호 | 작업 | 완료 조건 | 상태 |
|---|---|---|---|
| P-01 | README 작성 | 내가 파일을 열어 현재 상태가 "만들기 전"인지 확인 | 완료 |
| P-02 | AGENTS 작성 | 새 대화에서 AI가 규칙을 설명함 | 완료 |
| P-03 | 첫 결정 기록 (D-001) | DECISIONS에 내가 정한 방향만 있음 | 완료 |
| P-04 | 무엇을 만들지 정하기 (PRD) | 내가 PRD를 확정함 | 예정 |
| P-05 | 구조 정하기 (ARCHITECTURE) | 내가 구조를 확정함 | 예정 |
| P-06 | 화면 설계 (SCREEN-SPEC) | 모든 영역에 빈 결과·처리 중·오류가 있음 | 예정 |
| P-07 | 데이터 설계 (DATA-MODEL) | 필드 이름과 뜻이 PRD·화면과 같음 | 예정 |
| P-08 | API 설계 (API-SPEC) | 사용자 행동마다 성공·실패가 정해짐 | 예정 |
| P-09 | 시험지 (TEST-PLAN) | Must마다 시나리오가 있고 기대 결과가 눈으로 확인 가능 | 예정 |

## 실제 검증 결과
- README, DECISIONS: 파일을 열어 내용을 확인함
- AGENTS: 새 대화에서 AI가 규칙을 설명하고, 없는 파일은 없다고 말함

## 남은 문제와 다음 행동
- 아직 정하지 않은 것: 사용할 기술, 저장 방식 → STEP 6에서 정함
- 다음에 할 일: P-04 PRD 작성
```
