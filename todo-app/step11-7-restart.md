## 🧸 쉽게 말하면

컴퓨터를 끄면 **화면 서버와 API 서버도 꺼져요.** 다음 날 앱을 쓰려면 다시 켜야 해요.
이 방법을 README에 적어 두면, **내일의 나도, 친구도, 새 AI 대화도** 바로 켤 수 있어요.

## 🔌 켜는 순서 (2개의 터미널)

```
① 터미널 1: API 서버 켜기 (주방 먼저)
   backend 폴더로 이동 → 서버 실행 → http://localhost:8000/health 확인

② 터미널 2: 화면 서버 켜기 (거실)
   frontend 폴더로 이동 → 화면 실행 → http://localhost:5173 열기

③ 브라우저에서 확인
   어제 만든 카드가 그대로 있나? 상단에 "서버 연결됨"이 보이나?
```

> 💡 **왜 서버를 먼저?** 화면이 먼저 켜지면 "서버 연결 안 됨"이 잠깐 보일 수 있어요.

**AI가 알려 줄 명령 예시 (외울 필요 없어요)**

```bash
# 터미널 1
cd backend
uv run uvicorn main:app --reload --port 8000

# 터미널 2
cd frontend
npm run dev
```

> 📌 처음 받은 컴퓨터(다른 사람 컴퓨터)라면 먼저 `uv sync`와 `npm install`로 부품을 받아야 해요.

## 🔄 함께 고치기

| 바뀐 것 | 고칠 파일 | 고칠 칸 | 이유 |
|---|---|---|---|
| 실제로 켠 순서 확인 | README | 실행 방법 (전체 정리) | 다음 사람이 그대로 따라 하게 |
| 빠진 정보 발견 | README | 실행 방법 | 추측 없이 켜게 |
| 명령·포트가 바뀌었다면 | AGENTS | 환경 | README와 같은 말을 하게 |
| 다시 켜기 성공 | PLAN | P-19 상태, 실제 검증 결과, 다음 행동 | 진행 상황 |

- claude-code 입력
```claude-code
방금 실제로 켠 순서대로 README.md "실행 방법"을 고치는 초안을 보여 주세요. 포함할 것:
- 처음 한 번만 하는 준비 (부품 받기)
- 매번 켜는 순서 (서버 먼저, 화면 다음, 각각 다른 터미널)
- 확인할 주소 (/health, 화면 주소)
- 끄는 방법
- 저장소 파일 위치 (DATA-MODEL과 같게)
실행해 보지 않은 명령은 쓰지 마세요.
AGENTS.md 환경 칸과 다른 곳이 있으면 함께 알려 주세요.
```

**완성 예시**

```markdown
## 실행 방법

### 처음 한 번
- backend 폴더에서 `uv sync`
- frontend 폴더에서 `npm install`

### 매번 켜기 (터미널 2개, 서버 먼저)
1. 터미널 1: `cd backend` → `uv run uvicorn main:app --reload --port 8000`
   - 확인: http://localhost:8000/health → {"status": "ok"}
2. 터미널 2: `cd frontend` → `npm run dev`
   - 확인: http://localhost:5173 (상단에 "서버 연결됨")

### 끄기
- 각 터미널에서 `Ctrl + C`

### 데이터
- 할 일은 `backend/data/taskflow.db`에 저장됩니다. 이 파일을 지우면 카드가 모두 사라집니다.
```
