<details>
<summary>👀 예시 답 보기 (워크북 과정 기준 후보)</summary>

| 결정 | 내용 |
|---|---|
| 우선순위 | LOW·NORMAL·HIGH (화면: 낮음·보통·높음), 기본 NORMAL. **색만으로 구분하지 않고 글자도 표시** |
| 마감일 | 선택. 비우면 "마감일 없음" |
| 기한 초과 | 마감일이 오늘보다 **이전**이고 상태가 **완료가 아니면** 기한 초과. 오늘 마감은 기한 초과 아님. 저장하지 않고 **계산해서 표시** |
| 정렬 | ① 상태별 열은 그대로 ② 기한 초과 먼저 ③ 높음→보통→낮음 ④ 가까운 마감일 먼저 ⑤ 마감일 없는 카드는 뒤 ⑥ 나머지가 같으면 만든 순서와 번호로 고정 |
| 기존 카드 | 우선순위 보통, 마감일 없음 |

</details>

- claude-code 입력
```claude-code

PRD에는 "## 업무 규칙"에 기한 초과와 정렬 규칙을 같은 문장으로 추가하는 초안을 보여 주세요.
```

## 🗣️ 4. API 약속: 수정 요청의 세 가지 상태 ⭐

수정 요청에서 마감일 칸은 **세 가지 상태**가 있어요. 구분하지 않으면 **제목만 고쳤는데 마감일이 사라지는** 오류가 생겨요.

| 수정 요청에서 마감일이 | 의미 | 결과 |
|---|---|---|
| 아예 없음 (안 보냄) | 건드리지 않음 | 기존 마감일 유지 |
| `"2026-10-10"` (값) | 바꿈 | 새 날짜 저장 |
| `null` | 지움 | 마감일 없음 |
| `"2026-13-40"` (잘못된 날짜) | 오류 | 422, 저장 안 함 |
| 우선순위 `"URGENT"` | 오류 | 422, 저장 안 함 |

- claude-code 입력
```claude-code
위 세 가지 상태와 오류 규칙을 API-SPEC "## 변경 검토"와 "API 계약 결정 기록"에 추가하는 초안을 보여 주세요.
화면을 거치지 않은 잘못된 값도 서버가 거절해야 합니다.
DATA-MODEL에는 priority(LOW/NORMAL/HIGH, 기본 NORMAL)와 due_date(날짜 또는 없음) 필드를, SCREEN-SPEC에는 입력 칸과 카드 표시(우선순위 글자, "기한 초과 · 날짜", "오늘 마감", "마감 날짜")를 추가하세요.
```
