# STEP 11-0. 코드 만들기 — 전체 안내와 작업 지시서

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| PLAN.md | 지금까지의 작업과 다음 행동 | 구현 작업(P-10~)을 **이어서** 추가하고, "구현 인계"(작업 지시서)를 써요. |
| PRD.md | Must | 구현 범위 = Must. **그 밖의 것은 만들지 않아요.** |
| ARCHITECTURE.md | 화면·서버·저장소, 기술 | 어떤 폴더(frontend·backend)에 무엇을 만들지 정해요. |
| SCREEN-SPEC · DATA-MODEL · API-SPEC | 상세 설계 | 구현할 때 AI가 **읽어야 할 문서 목록**이 돼요. |
| TEST-PLAN.md | 시나리오 | 구현 단계마다 **무엇으로 확인할지** 정해요. |

## ⭐ STEP 11 전체에서 지키는 3가지

| 규칙 | 왜? |
|---|---|
| **새 대화에서 시작** | 기획 대화에는 거절한 아이디어가 섞여 있어요. **확정된 파일만** 보고 만들어야 해요. |
| **한 번에 하나만 승인** | 한꺼번에 만들면 고장 났을 때 어디가 문제인지 몰라요. |
| **매번 내 눈으로 확인** | AI의 "다 됐어요"는 증거가 아니에요. 화면을 직접 봐요. |

## 🗣️ 시작 전: PLAN에 "작업 지시서" 쓰기 (기획하던 대화에서)

### 대화 1. 구현 작업과 구현 인계 추가

- claude-code 입력
```claude-code
이제 구현 단계로 넘어갑니다. PLAN.md를 아래처럼 고치는 초안을 보여 주세요. 아직 저장하지 마세요.
1. "이번 목표와 범위": 목표를 "PRD Must를 동작하는 웹앱으로 만들기"로, 하지 않을 일은 "PRD에 없는 기능, 앱 안의 AI 기능, 인터넷 공개"로
2. "작업 목록"에 아래 작업을 "예정"으로 추가하고 완료 조건을 적기
   - P-10 도구 확인 / P-11 화면 틀 / P-12 서버 틀 / P-13 화면·서버 연결
   - P-14 카드 만들기 / P-15 목록·새로고침 유지 / P-16 상태 바꾸기 / P-17 수정·삭제 / P-18 실패 안내
   - P-19 껐다 켜고 다시 실행 / P-20 전체 시험과 기준점
3. 새 칸 "구현 인계" 추가
   - 승인한 작업 범위: 작업 목록 P-10~P-20을 한 번에 하나씩
   - 유지할 동작과 금지할 변경: PRD에 없는 기능 금지, 확정 문서의 이름·규칙을 바꾸지 않음
   - 읽을 요구·설계·TEST-PLAN 항목: PRD, ARCHITECTURE, SCREEN-SPEC, DATA-MODEL, API-SPEC, TEST-PLAN
   - 다음 실행 위치와 확인할 명령: P-10 도구 확인부터
   - 중단 조건과 복구 방법: 문서끼리 다르거나 정하지 않은 것이 나오면 멈추고 질문. 문제가 생기면 마지막 커밋으로
```

**이 문장을 넣는 이유**

| 문장 | 이유 |
|---|---|
| "하지 않을 일" | 목수가 방을 더 짓지 않게 |
| "한 번에 하나씩" | 고장 위치를 바로 알 수 있게 |
| "중단 조건" | 문서와 다른 걸 만들기 전에 멈추게 |

- [ ] 작업마다 완료 조건이 TEST-PLAN 시나리오와 연결되어 있나요?
- [ ] 금지할 변경이 있나요?

- claude-code 입력
```claude-code
좋습니다. PLAN.md에 저장하고 바뀐 부분을 보여 주세요. 그리고 "docs: add implementation handoff" 메시지로 커밋하세요.
```

저장했으면 **이 대화는 닫고**, 11-1부터는 **새 대화**를 열어요.

## 🔄 STEP 11 동안 함께 고치는 것

| 언제 | 고칠 파일 | 고칠 칸 |
|---|---|---|
| 작업마다 | PLAN | P-번호 상태, 실제 검증 결과, 다음 행동 |
| 11-2, 11-3, 11-7 | README | 실행 방법 (**실제로 실행한 명령**만) |
| 11-3 | AGENTS | 환경 (실제 버전, 포트) |
| 만들다가 **문서와 다르게** 해야 할 때 | 해당 설계 문서 **먼저** → 코드 | 문서가 기준 |
| 오류를 고쳤을 때 | PLAN | 실제 검증 결과 (오류, 원인, 수정) |

> 💡 AI가 문서에 없는 걸 만들었으면 **멈추고**, 넣을지 결정해요. 넣는다면 PRD·DECISIONS부터 고치고, 아니면 코드에서 빼요.
