# STEP 3. DECISIONS.md — "우리가 정한 것" 반 회의록

> **DECISIONS.md** = 제품을 어떻게 만들지 **사람이 확정한 중요한 선택과 그 이유**
> 한 번 적으면 지우지 않고, 새 결정이 생기면 **아래에 추가**해요.

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| README.md | 한 줄 소개 ("할 일 카드 웹앱, AI 기능 없음") | README에 적은 **방향을 사람이 확정**해서 첫 결정(D-001)으로 남겨요. |
| AGENTS.md | "결정은 사람이 한다", "확정되지 않은 것을 확정처럼 적지 않는다" | AI가 **빈 파일을 채우려고 결정을 지어내지** 않게 하는 근거예요. |

## 🔗 이 파일을 나중에 참고하는 곳

| 파일·단계 | 무엇을 가져가나 |
|---|---|
| STEP 4 PLAN | D-001 → 할 일 목록의 근거 |
| STEP 5 PRD | D-001의 범위 → 요구사항이 벗어나지 않게 |
| STEP 6 ARCHITECTURE | 구조 결정(D-003)의 번호 |
| 모든 새 대화의 AI | "이건 정해진 거라 바꾸면 안 돼" 판단 |

---

## 🧸 쉽게 말하면

DECISIONS는 **반 회의록**이에요. "소풍은 놀이공원으로 정했다. 이유는 다수결." 처럼 **정한 것과 이유**를 적어요.

```
📝 반 회의록
  [1번 결정] 소풍 장소: 놀이공원
  이유: 투표에서 가장 많이 나옴
  지금도 유효함: 예
```

---

## ❓ 왜 필요할까?

| DECISIONS가 없으면 | DECISIONS가 있으면 |
|---|---|
| 한 달 뒤 "왜 이렇게 만들었지?" 기억 안 남 | 이유가 적혀 있음 |
| 새 AI가 "AI 추천 기능도 넣을게요" 하고 마음대로 정함 | "AI 기능 없음"이 결정으로 남아 있어 멈춤 |
| 정한 것과 아직 고민 중인 것이 섞임 | **확정한 것만** 있음 |

### 다른 파일과 뭐가 달라요?

| 파일 | 적는 것 | 예 |
|---|---|---|
| AGENTS | AI가 **일하는 방식**의 규칙 | "허락 전엔 파일을 바꾸지 않는다" |
| **DECISIONS** | 제품에 대해 **왜** 그렇게 정했나 | "AI 기능은 넣지 않는다. 이유는…" |
| PLAN (다음) | **어떤 순서로, 어디까지** 했나 | "P-04 PRD 작성: 진행 중" |
| PRD (STEP 5) | **무엇을** 만드나 | "빈 제목은 저장하지 않는다" |

### DECISIONS에 적을지 고민될 때 묻는 질문

> **"6개월 뒤에 '이건 왜 이렇게 만들었지?'라고 물을 만한가?"**
> - 예 → DECISIONS (예: 완료 카드 되돌리기 허용, React·FastAPI 구조)
> - 아니요, 오늘 작업 순서일 뿐 → PLAN (예: 오늘은 PRD부터 쓰기)

## 📍 언제 만들까?

**무언가를 처음 "확정"한 순간.** README에 적은 "할 일 카드 웹앱, AI 기능 없음"을 확정하면 지금이에요.

> ⚠️ **아직 정하지 않은 건 절대 적지 않아요.**
> "React를 쓴다", "로그인을 넣는다"를 미리 적으면 안 돼요. 고민 중인 것은 PLAN의 "남은 문제"나 PRD의 "열린 질문"에 둬요.

---

## 🗣️ AI와 대화하며 만들기

### 대화 1. 결정 하나에 무엇을 적어야 할지 물어보기

- claude-code 입력
```claude-code
README.md와 AGENTS.md를 읽으세요. DECISIONS.md를 만들려고 합니다. 이 파일에는 제가 확정한 결정만 적습니다.
1년 뒤의 제가 결정 하나를 읽을 때 알고 싶을 질문을 5~6개 알려 주세요.
아직 파일은 만들지 마세요.
```

**AI 대답 예시**
> 1. 이 결정을 어떻게 찾나요? (번호와 제목)
> 2. 무엇을 정했나요?
> 3. 왜 그렇게 정했나요?
> 4. 어디에 적용되나요?
> 5. 관련 문서는 무엇인가요?
> 6. 지금도 유효한가요?

---

### 대화 2. 질문을 "항목 이름"으로 바꾸기

DECISIONS는 칸이 아니라 **결정 하나마다 같은 항목 6개**를 적어요.

| 질문 | 항목 이름 |
|---|---|
| 어떻게 찾나요? | |
| 무엇을 정했나요? | |
| 왜 그렇게 정했나요? | |
| 어디에 적용되나요? | |
| 관련 문서는? | |
| 지금도 유효한가요? | |

<details>
<summary>👀 예시 답 보기</summary>

결정 번호와 제목 / 결정 내용 / 결정 이유 / 적용 범위 / 관련 기준 문서 / 유효 상태

- 번호는 **D-001**부터. 지우거나 다시 쓰지 않아요.
- 유효 상태는 **"적용 중"** 또는 **"후속 결정으로 대체됨"** 둘 중 하나.
- "결정자", "승인일" 칸은 두지 않아요. (확정한 것만 적으니까 유효 상태로 충분)

</details>

### 대화 3. 첫 결정 기록하기

- claude-code 입력
```claude-code
제가 확정한 결정은 이것 하나입니다.
"브라우저에서 할 일을 카드로 관리하고, 사용자가 상태를 직접 바꾸는 웹앱을 만든다. 앱 안에 AI 기능은 넣지 않는다."
이 결정만 D-001로 DECISIONS.md에 적어 주세요.
항목은 결정 번호와 제목, 결정 내용, 결정 이유, 적용 범위, 관련 기준 문서, 유효 상태입니다.
관련 기준 문서는 지금 있는 README.md로 적고, 아직 없는 파일은 적지 마세요.
기술(React 등)이나 상세 기능은 제가 정하지 않았으니 넣지 마세요.
초안을 대화에만 보여 주세요.
```

**AI 대답 예시**

```markdown
# 확정 결정

사람이 확정한 주요 결정만 적습니다. 결정을 바꿀 때는 지우지 않고 새 번호로 추가합니다.
아직 정하지 않은 것은 PLAN의 "남은 문제"나 PRD의 "열린 질문"에 둡니다.

## D-001 카드형 할 일 웹앱
- 결정 내용: 브라우저에서 할 일을 카드로 관리하고 사용자가 상태를 직접 바꾼다. 앱 안에 AI 기능은 넣지 않는다.
- 결정 이유: 할 일과 진행 상태를 직접 확인하는 앱을 만든다.
- 적용 범위: Task Flow 제품 전체
- 관련 기준 문서: README.md 소개
- 유효 상태: 적용 중
```

| 이번에 바뀐 것 | 함께 고칠 파일 | 고칠 칸 | 이유 |

```
DECISIONS에 D-번호 추가 → 영향받는 문서(PRD·설계) 수정 → PLAN 기록 → (큰 변화면) README 현재 상태
```

## 🚫 자주 하는 실수

| 실수 | 고치는 방법 |
|---|---|
| 고민 중인 것도 적음 | 확정한 것만. 고민 중은 PLAN 남은 문제 / PRD 열린 질문 |
