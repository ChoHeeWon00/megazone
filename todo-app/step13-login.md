```
지금                          바꾼 뒤
📓 공용 공책                   🔒 철수 사물함   🔒 영희 사물함
  - 철수: 숙제                    - 숙제          - 줄넘기
  - 영희: 줄넘기                  (영희 것 안 보임) (철수 것 안 보임)
```

- **가입**: 사물함 만들기 / **로그인**: 열쇠로 열기 / **로그아웃**: 잠그기
- **세션**: "이 사람은 방금 열쇠로 연 사람이에요"라는 **출입증**. 브라우저는 출입증 번호(쿠키)를 들고 다니고, 서버는 그 번호가 진짜인지 확인해요.

| 결정할 질문 | 내 결정 |
|---|---|

| 비밀번호 규칙과 같은 이메일로 다시 가입할 때 안내는? | |
| 기존 Task는 누구 것이 되나? | |

<details>
<summary>👀 예시 답 보기</summary>

| 질문 | 결정 |
|---|---|

### ⑨ 두 계정 교차 검수 ⭐ (P-25)

**브라우저 창 2개**(하나는 시크릿 창)로 A와 B를 동시에 열어요.

| 행동 | 기대 | 실제 | 판정 |
|---|---|---|---|
| 로그인 전 화면 열기 | 로그인 화면 | | |
| 틀린 비밀번호 | "이메일 또는 비밀번호가 맞지 않아요" | | |
| A 로그인 | 이전된 기존 Task가 모두 보임 | | |
| B 가입 | 빈 보드 (A의 Task 안 보임) | | |
| B가 카드 만들기 → A 새로고침 | A 화면에 B 카드 없음 | | |
| B가 A의 Task 수정 요청 (/docs에서) | 404, A의 Task 그대로 | | |
| 로그아웃 → 새로고침 | 로그인 화면 유지 | | |
| 로그인한 채로 기존 시나리오 T-01~ | 원래처럼 통과 | | |

> 💡 **서버 직접 시험**: `/docs`에서는 쿠키를 넣기 어려울 수 있어요. AI에게 "B로 로그인한 상태에서 A의 Task를 수정 요청하는 방법"을 물어보거나, 자동 테스트 결과로 확인해요.
> 💡 **만료 시험**: AI에게 "개발용 DB에서 내 세션 만료 시각을 과거로 바꾸는 방법"을 물어 실제로 확인해 보세요. 빈 보드가 아니라 **로그인 안내**가 나와야 해요.

## 😵 막혔을 때

| 보이는 것 | 뜻 | AI에게 할 말 |
|---|---|---|
| 로그인은 성공했는데 다음 요청이 계속 401 | 브라우저가 쿠키를 안 보냄 | "화면 요청에 쿠키를 함께 보내는 설정과, 서버 CORS에 쿠키 허락(credentials)이 있는지 확인해 주세요" |
| Console: CORS 오류 (로그인 뒤에만) | 쿠키를 쓰면 CORS에 "모든 주소 허락"을 쓸 수 없음 | "CORS 허락 주소가 화면 주소 하나로 정확히 적혀 있는지 확인해 주세요" |
| 이전 뒤 Task가 안 보임 | 이전용 계정이 아닌 다른 계정으로 로그인 | "기존 Task가 연결된 계정 이메일을 DB에서 확인해 주세요" |
