# STEP 1. README.md — 프로젝트의 "표지" 만들기

> **README.md** = "이게 뭐고, 지금 어떤 상태이고, 어떻게 실행해?" (**사람**이 읽는 파일)

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| (없음) | - | **가장 먼저 만드는 파일**이에요. 내 머릿속 아이디어만 있으면 돼요. |

## 🔗 이 파일을 나중에 참고하는 곳

| 파일·단계 | 무엇을 가져가나 |
|---|---|
| STEP 2 AGENTS | "무슨 프로젝트인지" → AI 규칙의 목적 |
| STEP 3 DECISIONS | 한 줄 소개의 방향 → 첫 결정 D-001로 확정 |
| 모든 새 대화의 AI | 현재 상태 → "어디까지 됐는지" 착각하지 않기 |

---

## 🧸 쉽게 말하면

README는 **책의 표지와 차례**예요. 처음 이 폴더를 연 사람이 **제일 먼저 읽는 파일**입니다.

```
📕 책 표지를 보면 알 수 있는 것
   - 무슨 책인지 (제목, 소개)
   - 지금 어디까지 썼는지
   - 어떻게 읽는지
```

---

## ❓ 왜 필요할까?

| README가 없으면 | README가 있으면 |
|---|---|
| 내일의 나: "이 폴더 뭐였지?" | 첫 줄만 봐도 알 수 있음 |
| 새 AI 대화: "이미 다 만든 앱인가?" 하고 착각 | "아직 만들기 전"이라고 적혀 있어 착각 안 함 |
| 친구: "어떻게 실행해?" 매번 물어봄 | 실행 방법이 적혀 있음 |

> ⚠️ **실제로 자주 생기는 실수**
> README에 앱 소개만 써 두면, 다음 날 AI가 "소개가 있으니 다 만들어도 되겠다"며 **허락 없이 코드를 만들어 버려요.**
> 그래서 **"현재 상태: 아직 만들기 전"**을 꼭 적어야 해요.

---

## 🗣️ AI와 대화하며 만들기

### 대화 1. README에 무엇이 필요한지 물어보기

바로 "README 만들어 줘"라고 하지 않아요. **먼저 무엇이 필요한지 질문을 받아요.**

- claude-code 입력
```claude-code
할 일 카드 웹앱을 만들려고 합니다. 아직 아무 파일도 없습니다.
README.md는 이 폴더를 처음 여는 사람이 제일 먼저 읽는 파일입니다.
그 사람이 궁금해할 질문을 4~5개만 알려 주세요.
아직 파일은 만들지 마세요.
```

**이 문장을 넣는 이유**

| 문장 | 이유 |
|---|---|
| "처음 여는 사람이 읽는 파일" | 누가 읽는지 알려 줘야 AI가 맞는 질문을 함 |
| "질문을 알려 주세요" | 내용 대신 **질문**을 받아야 내가 이해하고 고를 수 있음 |
| "아직 파일은 만들지 마세요" | 규칙 ② 허락 전엔 손대지 않게 |

**AI 대답 예시**
> 1. 이 프로젝트는 무엇이고 누구를 위한 건가요?
> 2. 지금 어디까지 만들어졌나요?
> 3. 어떤 문서들이 있나요?
> 4. 처음 받으면 무엇부터 하나요?
> 5. 어떻게 실행하나요?

|---|---|

| 어떻게 실행하나요? | |

### 대화 3. 내용을 대화로 먼저 받기

- claude-code 입력
```claude-code
README.md를 아래 칸으로 만들려고 합니다.
- 맨 위: 제목과 한 줄 소개
- 현재 상태
- 프로젝트 문서
- 시작 방법
- 실행 방법
- 확인과 기록
이 앱은 할 일을 카드로 만들고 상태(할 일, 진행 중, 완료)를 바꾸는 웹앱입니다. 앱 안에 AI 기능은 넣지 않습니다.
아직 아무것도 만들지 않았으므로 "현재 상태"에는 만들기 전이라고 쓰고, "실행 방법"은 아직 미정이라고 쓰세요.
"프로젝트 문서"에는 지금 있는 README.md만 적으세요. 아직 없는 파일은 적지 마세요.
초안을 대화에만 보여 주고 파일은 아직 만들지 마세요.
```

**이 문장을 넣는 이유**

| 문장 | 이유 |
|---|---|
| "앱 안에 AI 기능은 넣지 않습니다" | AI가 "AI 추천 기능"을 붙이지 않게 |
| "현재 상태에는 만들기 전이라고" | 다음 AI가 착각하지 않게 |
| "실행 방법은 아직 미정" | 실행해 보지 않은 명령을 지어내지 않게 |
| "아직 없는 파일은 적지 마세요" | 파일이 생길 때마다 한 줄씩 추가 (함께 고치기) |

**AI 대답 예시**

```markdown
# Task Flow

카드로 할 일을 관리하고 진행 상태를 확인하는 웹앱입니다. 앱 안에 AI 기능은 넣지 않습니다.

## 현재 상태
아직 만들기 전입니다. 무엇을 만들지 정하는 중이며 코드와 개발환경은 준비하지 않았습니다.

## 프로젝트 문서
- README.md: 이 프로젝트의 소개와 현재 상태

## 시작 방법
task-flow 폴더를 열고 README.md부터 읽습니다.

## 실행 방법
아직 미정입니다. 실제로 실행해 본 뒤에 적습니다.

## 확인과 기록
AI가 파일을 저장하면 실제 파일을 열어 내 결정과 같은지 확인합니다.
```

### 대화 4. 확인하고 저장하기

- [ ] 내가 말하지 않은 기능(로그인, AI 추천 등)이 들어가지 않았나요?
- [ ] "실행 방법"에 실행해 본 적 없는 명령이 없나요?

- claude-code 입력
```claude-code
초안이 좋습니다. README.md 파일로 저장하고 저장된 내용을 그대로 보여 주세요.
```

> 💡 **저장한 뒤에는 꼭 파일을 직접 열어 보세요.** AI가 "저장했어요"라고 해도 실제 파일이 다를 수 있어요.

## 🔄 함께 고치기 — README는 끝까지 계속 자라요

README는 **다른 STEP을 할 때마다** 조금씩 고쳐요. 아래 시점을 기억하세요.

| 언제 | README에서 고칠 칸 | 무엇으로 |
|---|---|---|
| 새 파일을 만들 때마다 (STEP 2~10) | 프로젝트 문서 | 새 파일 이름과 한 줄 역할 추가 |
| STEP 2 (AGENTS) 뒤 | 시작 방법 | "README와 AGENTS부터 읽는다" |
| STEP 5 (PRD 확정) 뒤 | 현재 상태 | "요구사항 확정, 설계 전" |
| STEP 10 (설계 끝) 뒤 | 현재 상태 | "설계 확정, 구현 전" |
| STEP 11-2, 11-3, 11-7 | 실행 방법 | **실제로 실행해 본** 명령 |
| STEP 12 | 현재 상태, 제품 기준점(새 칸) | "MVP 완성", 기준점 기록 |

> 지금은 다른 파일이 없으니 함께 고칠 파일이 없어요.
