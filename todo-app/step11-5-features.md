# STEP 11-5. 기능 하나씩 만들기 — 방 하나씩 꾸미기 (PLAN P-14 ~ P-18)

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| PLAN.md | 구현 인계, P-14~P-18 | **이번 방 하나만** 만들고, 금지할 변경을 지켜요. |
| PRD.md | Must, 인수 조건 | 만들 기능의 **범위와 정답**이에요. |
| SCREEN-SPEC.md | 영역, 빈 결과·처리 중·오류 | 화면을 **문서에 적힌 대로** 만들어요. |
| DATA-MODEL.md | 필드 이름, 상태 값, 저장 규칙 | 저장소 표와 이름을 **그대로** 써요. |
| API-SPEC.md | 주소, 요청·응답, 오류 | 화면과 서버가 **같은 약속**으로 대화하게 해요. |
| TEST-PLAN.md | 시나리오 | 방을 다 꾸민 뒤 **무엇으로 확인할지**예요. |
| DECISIONS.md | D-002, D-004 | 되돌리기 버튼, 따로 뜨는 생성 창을 빠뜨리지 않게 해요. |

## 🧸 쉽게 말하면

이제 진짜 기능을 만들어요. **한 번에 방 하나씩.** 한 방을 다 꾸미고 확인한 뒤 다음 방으로 가요.

## 🗺️ 만드는 순서 (5개의 방)

| PLAN | 방 (기능) | 확인할 TEST-PLAN 시나리오 | 왜 이 순서? |
|---|---|---|---|
| P-14 | ① 카드 만들기 + 저장 | Task 생성, 빈 제목, 띄어쓰기만 | 카드가 있어야 나머지를 시험할 수 있어요 |
| P-15 | ② 목록 보기 + 새로고침 유지 | 새로고침 유지, 빈 보드 | 저장된 걸 다시 불러와야 해요 |
| P-16 | ③ 상태 바꾸기 | 상태 변경, 완료 되돌리기 | 카드가 있어야 옮길 수 있어요 |
| P-17 | ④ 수정·삭제 | 제목만 수정, 삭제 취소·확인 | 기본 흐름이 된 뒤에 |
| P-18 | ⑤ 실패 안내 다듬기 | 저장 실패, 서버 꺼짐 | 모든 기능이 실패도 안내하는지 |

> 💡 방마다 **같은 5단계**를 반복해요: **계획 → 승인 → 내 눈으로 확인 → 함께 고치기 → 저장**

## 🔁 방 하나를 꾸미는 5단계 (① 카드 만들기 예시)

### 1) 계획 받기

- claude-code 입력
```claude-code
PLAN의 P-14를 "진행 중"으로 바꾸세요.
PLAN.md의 구현 인계와 확정 문서(PRD, SCREEN-SPEC, DATA-MODEL, API-SPEC, TEST-PLAN, DECISIONS)만 기준으로 합니다.
이번에는 ① 카드 만들기와 저장만 구현하려고 합니다.
1. 바꿀 파일과 각각 하는 일을 보여 주세요. (화면, 서버, 저장소 나눠서)
2. API-SPEC의 어떤 주소와 DATA-MODEL의 어떤 필드를 쓰는지 알려 주세요.
3. 확인할 TEST-PLAN 시나리오를 알려 주세요.
4. 문서끼리 다르거나 정해지지 않은 것이 있으면 먼저 질문하세요.
아직 코드를 바꾸지 마세요.
```

**AI 대답 예시**
> - 저장소: `tasks` 표를 만들어요 (DATA-MODEL의 6개 필드)
> - 서버: `POST /api/tasks`를 만들고 빈 제목·띄어쓰기만 있는 제목은 422로 거절해요 (API-SPEC)
> - 화면: 따로 뜨는 생성 창에서 저장하면 서버로 보내요 (SCREEN-SPEC, D-004)
> - 확인할 시나리오: T-01, T-02, T-03
> - 질문: 저장소 파일 위치를 `backend/data/taskflow.db`로 해도 될까요?

- [ ] 이번 방(①)만 만드나요? 목록·삭제까지 만들려고 하지 않나요?
- [ ] 문서에 있는 이름(title, status 등)을 그대로 쓰나요?
- [ ] AI가 질문한 게 있으면 **내가 답했나요?**

### 2) 승인하기

- claude-code 입력
```claude-code
저장소 위치는 backend/data/taskflow.db로 합니다. ①만 승인합니다.
구현한 뒤 바뀐 파일, 실행한 명령, 확인 결과를 보고하세요.
제가 화면에서 직접 확인하기 전에는 P-14를 "확인 대기"로 두세요.
```

### 3) 내 눈으로 확인하기 ⭐

TEST-PLAN을 옆에 펴 놓고 **직접** 해 봐요.

| 시나리오 | 내가 한 행동 | 정답 | 실제로 보인 것 | 맞나? |
|---|---|---|---|---|
| T-01 Task 생성 | 제목 "숙제하기" 저장 | 할 일 칸에 카드 | | |
| T-02 빈 제목 | 제목 없이 저장 | 저장 안 됨, 이유 보임 | | |
| T-03 띄어쓰기만 | 제목에 띄어쓰기만 | 저장 안 됨, 이유 보임 | | |

> 💡 **서버도 직접 시험해요.** `http://localhost:8000/docs`에서 `POST /api/tasks`를 눌러 **화면을 거치지 않고** 빈 제목을 보내 보세요. 서버도 거절하나요?

> 💡 **버튼과 안내 글자를 소리 내어 읽어 보세요.** 실제 리허설에서 "완료**으로**"처럼 틀린 글자가 나왔어요. 시험 항목은 통과해도 글자는 틀릴 수 있어요.

- 다 맞으면 → 4)로
- 다르면 → **11-6 오류 대처**로

### 4) 함께 고치기

| 바뀐 것 | 고칠 파일 | 고칠 칸 |
|---|---|---|
| 방 확인 끝 | PLAN | P-번호 "완료", 실제 검증 결과, 다음 행동 |
| 만들다가 **문서에 없던 것**을 정함 (예: 저장소 파일 위치) | 해당 문서 | DATA-MODEL "SQLite 변환 초안" / ARCHITECTURE "기술과 실행 환경" |
| 만들다가 **문서와 다르게** 해야 했음 | 해당 설계 문서 **먼저** | 문서를 고친 뒤 코드가 맞는지 다시 확인 |

- claude-code 입력
```claude-code
①을 TEST-PLAN T-01~T-03으로 직접 확인했습니다. 함께 고칠 곳을 표로 먼저 보여 주세요.
- PLAN.md: P-14 "완료", 실제 검증 결과, 다음 행동 "P-15"
- 이번 구현에서 문서에 없던 것을 정했다면(예: 저장소 파일 위치) 그 문서와 위치
- 코드가 설계 문서와 다른 곳이 있다면 그 위치
확인하면 고치고 바뀐 줄만 보여 주세요.
```

### 5) 저장하기

- claude-code 입력
```claude-code
바뀐 파일 목록을 보여 주고 "feat: create task" 메시지로 커밋하세요.
```

## 📋 나머지 방 요청 예시

방마다 **1) 계획 프롬프트의 P-번호와 "이번에는 ___만"** 부분만 바꾸면 돼요.

| PLAN | "이번에는 ___만" | 특히 확인할 것 | 커밋 메시지 |
|---|---|---|---|
| P-15 | ② 목록 보기와 새로고침 뒤 유지 | 새로고침해도 카드가 남나? 카드 0개일 때 "카드가 없어요"가 보이나? | `feat: list tasks` |
| P-16 | ③ 상태 바꾸기 | 완료 → 진행 중 되돌리기가 되나? (D-002) | `feat: move task status` |
| P-17 | ④ 수정과 삭제 | 제목만 고쳐도 설명이 남나? 삭제 취소하면 남나? | `feat: edit and delete task` |
| P-18 | ⑤ 실패 안내 | 서버를 끄고 저장하면 카드가 생기지 않고 입력이 남나? **연결 상태 표시도 "연결 안 됨"으로 바뀌나?** | `feat: failure messages` |

## ⭐ 방을 하나 끝낼 때마다 "회귀 확인"

새 방을 꾸미다가 **예전 방을 망가뜨릴 수 있어요.** 그래서 매번 앞에서 된 것도 다시 확인해요.

```
③ 상태 바꾸기를 만든 뒤
  ✅ 상태가 바뀌나?            (새 기능)
  ❓ 카드 만들기는 여전히 되나?  (① 다시 확인)
  ❓ 새로고침해도 남나?         (② 다시 확인)
```

- claude-code 입력
```claude-code
③을 만들었습니다. 이번 변경 때문에 영향을 받을 수 있는 이전 시나리오를 TEST-PLAN 번호로 알려 주세요. 제가 직접 다시 확인하겠습니다.
```

### 다섯 방을 다 꾸민 뒤: 문서와 앱이 같은 말을 하나?

- claude-code 입력
```claude-code
새 기능을 추가하지 마세요. PRD, SCREEN-SPEC, DATA-MODEL, API-SPEC이 지금 만든 코드와 같은지 확인하세요.
다른 곳이 있으면 문서 위치, 코드 위치, 어느 쪽을 고쳐야 할지 표로 보여 주세요.
```

|---|---|

| 코드를 문서와 다르게 만들고 문서는 그대로 | 문서부터 고치기 (함께 고치기) |
