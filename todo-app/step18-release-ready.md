# STEP 18. 구조 정리와 배포 준비 (워크북 Day 15)

> 마지막 단계예요. 문서의 독자가 **"내가 없을 때 이 앱을 맡을 처음 보는 사람"**으로 바뀌어요.
> 목표는 **"지금 배포해도 되는지"를 증거로 판정**하는 것이에요. 실제로 인터넷에 공개하는 일은 하지 않아요.

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| README.md | 제품·품질 기준점, 실행 방법 | 출발점이자, **운영 정보를 추가할 곳**이에요. |
| ARCHITECTURE.md | 구성 요소와 책임 | 코드 폴더 구조(모듈 경계)를 이 책임에 맞춰요. |
| TEST-PLAN.md · 자동 테스트 | 보호 행동 | 구조를 바꿔도 **동작이 그대로인지** 증명해요. |
| DECISIONS.md | 지금까지의 결정 | 자동화의 경계(무엇을 자동으로, 무엇은 사람이)도 결정으로 남겨요. |
| DATA-MODEL.md | 저장소 위치 | 백업·복원 방법을 정해요. |
| PLAN.md | 작업 목록 | 배포 준비 판정을 기록해요. |

---

## 🧸 쉽게 말하면

**이사 가기 전 집 정리**예요. 다음에 살 사람(처음 보는 동료)이 헤매지 않게요.

| 이사 준비 | 할 일 웹앱 |
|---|---|
| 물건을 방별로 정리 | 코드를 책임별 폴더로 정리 (모듈 경계) |
| "보일러 켜는 법" 쪽지 | 같은 일을 반복하는 절차서 (playbook) |
| 매일 자동으로 도는 경보기 | 코드가 올라오면 자동으로 테스트 (CI) |
| 귀중품 복사본 | 데이터 백업과 **복원해서 확인** |
| 문제 생기면 돌아갈 방법 | 이전 상태 복구 계획 |
| 최종 점검표 | 배포 준비 판정 |

## 🗣️ 1. 출발점 확인과 독자 바꾸기

- claude-code 입력 (새 대화)
```claude-code
새 대화입니다. README, PRD, ARCHITECTURE, API-SPEC, DATA-MODEL, PLAN을 읽으세요. 아직 파일을 옮기거나 만들지 마세요.
1. 현재 실행 방법, 테스트 명령, build 명령, 데이터 파일 위치를 확인하고 테스트와 build를 실제로 실행해 결과를 보여 주세요.
2. 이 앱을 처음 보는 동료가 (1) 새 기능을 추가할 때, (2) 배포할 때, (3) 데이터를 복구할 때, (4) 배포 후 되돌릴 때
   문서에서 꼭 찾아야 할 질문을 4개씩 쓰고, 지금 README에 답이 있는지 "있음/없음"으로 표시하세요.
3. PLAN.md 작업 목록에 이어서 추가하세요: P-44 모듈 경계 / P-45 재사용 절차 / P-46 자동 검사(CI)와 build / P-47 백업·복원·복구 계획 / P-48 배포 준비 판정.
```

> 💡 **test와 build는 달라요.**
> test = "정해 둔 행동이 여전히 맞나?" / build = "배포용 파일 묶음을 만들 수 있나?"
> test가 통과해도 build가 실패할 수 있고, build가 성공해도 사용자 행동이 틀릴 수 있어요. **둘 다** 필요해요.

## 🗣️ 4. 자동 검사(CI)와 build (P-46)

**CI** = 코드가 저장소에 올라올 때 **테스트와 build를 자동으로 실행**하는 경보기예요. GitHub Actions라는 도구를 써요.

### 먼저 결정: 무엇을 자동으로, 무엇은 사람이?

| 자동으로 | 사람이 결정 |
|---|---|
| 서버 테스트, 화면 테스트, build | 실제 배포, DB 구조 변경 적용, 되돌리기 결정 |

> ⚠️ **테스트와 build가 통과했다고 배포해도 된다는 뜻은 아니에요.** 배포 승인은 사람이 해요.

- claude-code 입력
```claude-code
P-46을 시작합니다. 위 경계를 DECISIONS.md에 "자동화 결정"으로 추가하는 초안을 보여 주세요. (자동 실행 시점, 실행할 검사, 최소 권한, 자동화하지 않을 사람 승인, 실패하면 막는 기준)
그다음 로컬에서 성공한 명령과 같은 순서로 .github/workflows/quality.yml 초안을 보여 주세요. 실제로 원격에 올리지는 마세요.
```

- claude-code 입력 (확인한 뒤)
```claude-code
workflow 파일을 저장하고, 그 안의 명령을 로컬에서 같은 순서로 실행해 결과를 보여 주세요. 원격 CI는 실행하지 않았으므로 "미확인"으로 PLAN에 적으세요.
```

### production build 화면 확인 ⭐

build가 **성공한 것**과 build한 화면이 **동작하는 것**은 달라요.

- claude-code 입력
```claude-code
화면을 production build로 만들고 미리보기로 켜는 방법을 알려 주세요. 미리보기 주소에서 로그인과 카드 목록이 되는지 제가 확인하겠습니다.
서버가 그 주소를 허락하도록(CORS) 무엇을 바꿔야 하는지도 알려 주세요. 코드에 주소를 하드코딩하지 말고 설정(환경 변수)으로 바꾸게 하세요.
```

- [ ] build 화면에서 **로그인 → 카드 목록**이 보이나요?
- [ ] build 결과에 **비밀값이 들어가지 않았나요?**

> 💡 리허설에서 build 화면은 다른 방 번호(4173)를 써서, 서버의 허락 주소를 설정으로 바꿔야 로그인이 됐어요. 이 내용을 README 실행 방법에 적어요.

## 🗣️ 5. 백업·복원·복구 계획 (P-47)

> ⚠️ **백업 파일이 있다고 복구할 수 있는 건 아니에요.** 별도 위치에 **복원해서 읽어 보기 전에는** 확인한 게 아니에요.

- claude-code 입력
```claude-code
P-47을 시작합니다. 아래를 만들 계획을 먼저 보여 주세요.
1. 백업 스크립트: 서버가 켜져 있어도 안전한 방법으로 복사, 날짜가 들어간 이름, 최근 7개만 보관
2. 복원 확인 스크립트: 원본을 건드리지 않고 별도 위치에 복원해서 무결성, 사용자별 Task 수, 상태별 수, 소유자 없는 Task 수를 출력
백업 폴더는 Git에 올리지 않게 하세요. 승인하면 만들고 실제로 백업 → 복원 확인을 실행해 결과를 보여 주세요.
```

**리허설 결과**
```
무결성: ok
사용자별 Task 수: [('owner@example.test', 10), ('b@example.test', 1)]
상태별: {'DONE': 2, 'IN_PROGRESS': 2, 'TODO': 7}
소유자 없는 Task: 0
복원 위치(원본 아님): /tmp/.../restored.db
```

README에 두 칸을 추가해요.

```markdown
## 데이터 운영
- DB 위치와 권한:
- 백업 시점·이름·보관 개수·위치:
- 복원 확인 방법 (원본을 건드리지 않음):
- 복원 뒤 확인할 것: A·B로 로그인해 각자 Task 수 비교

## 이전 상태 복구 계획
- 되돌릴 조건과 결정하는 사람:
- 순서: 이전 태그 → 백업 DB → 서버 재시작 → 핵심 시나리오 확인
- 실패 원인과 다시 배포할 조건을 남길 곳:
```

## ✅ 6. 배포 준비 판정 (P-48) — 사람이 증거로

- claude-code 입력
```claude-code

관문: 문서·코드 구조 일치 / 서버·화면 테스트 / production build 화면 / 비밀값 노출 없음 / 백업·복원 / 되돌리기 계획 / 핵심 사용자 흐름(로그인·생성·상태·우선순위·검색) / 원격 CI
```

| 관문 | 증거 | 결과 |
|---|---|---|
| 구조·문서 일치 | ARCHITECTURE 모듈 경계 = 코드 | |
| 자동 테스트 | 서버 14 / 화면 5 통과 | |
| build 화면 | 로그인·목록 확인 | |

| 되돌리기 | 리허설 여부 | |
| 핵심 흐름 | TEST-PLAN 핵심 시나리오 | |
| 원격 CI | 실행 안 함 | 미확인 |

**판정**: 승인 / **승인 대기** / 보류

> 💡 미확인이 있으면 "승인 대기"가 정직한 판정이에요. **실패가 아니에요.** 무엇을 더 확인해야 하는지가 분명해졌다는 뜻이에요.

## 😵 막혔을 때

| 보이는 것 | 뜻 | AI에게 할 말 |
|---|---|---|
| 폴더를 옮긴 뒤 서버가 안 켜짐 | import 경로나 실행 명령이 바뀜 | "실행 명령은 그대로 두고 import만 고쳐 주세요. 테스트로 확인해 주세요" |
| build 화면에서 로그인 뒤에도 목록이 안 나옴 | 서버가 build 주소를 허락 안 함 | "서버 CORS 허락 주소를 설정으로 바꿀 수 있게 하고, build 미리보기 주소를 넣어 켜는 방법을 알려 주세요" |
| 백업 파일이 Git에 올라감 | .gitignore 누락 | "backups 폴더와 DB 파일을 .gitignore에 넣고 Git에서 빼 주세요" |
| AI가 "배포까지 해 드릴게요" | 범위 밖 | "외부 배포는 하지 않습니다. 판정 표만 만들어 주세요" |
