# STEP 15. 검색·필터와 통합 화면 (워크북 Day 12)

> 카드가 많아지면 찾기 어려워요. **검색어와 조건으로 원하는 카드만** 보고, 그 조건이 **주소(URL)에 남아** 새로고침해도 유지되게 해요.
> 이번엔 **어떤 칸이 필요한지까지** 내가 판단해요.

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| step13-0-change-cycle.md | 변경 사이클 | 같은 순서로 하되, **필요 없는 칸은 "변경 없음"으로 기록**해요. |
| README.md | 우선순위·마감일 기준점 | 출발점이에요. |

| API-SPEC.md | 목록 조회 주소 | 같은 주소에 **조건(쿼리)**을 붙여요. |

| SCREEN-SPEC.md | 대안과 결정 › 좁은 화면 배치 | 검색창이 생겨도 **320px 화면**에서 쓸 수 있게 해요. |

## 🗣️ 4. API 약속과 처리 순서 ⭐

| 이름 | 형식 | 생략하면 | 잘못된 값 |
|---|---|---|---|
| `q` | 앞뒤 빈칸 제거, 0~100자 | 검색 없음 | 100자 초과 → 422 |
| `status` | TODO, IN_PROGRESS, DONE | 모든 상태 | 422 |
| `priority` | LOW, NORMAL, HIGH | 모든 우선순위 | 422 |
| `due` | OVERDUE, TODAY, UPCOMING, NONE | 모든 기한 | 422 |

> ⚠️ **잘못된 값을 받으면 "전체 결과"가 아니라 오류(422)**로 알려요. 조용히 전체를 보여 주면 사용자는 조건이 적용된 줄 알아요.

**서버 처리 순서** (이 순서가 바뀌면 다른 사람 카드 개수가 드러날 수 있어요)

```
로그인 사용자 범위 → 검색(제목 OR 설명) → 필터(AND) → 정렬(STEP 14 규칙) → 결과와 개수
```

### 특수문자 `%`, `_` ⭐

데이터베이스 검색에서 `%`는 "아무 글자나 여러 개", `_`는 "아무 글자 하나"라는 **검색 기호**예요. 그대로 두면 `%`를 검색했을 때 **모든 카드**가 나와요.

```
❌ "%" 검색 → 모든 카드          (기호로 처리됨)
✅ "%" 검색 → "100% 완료 기준 쓰기"만  (일반 글자로 처리됨)
```

- claude-code 입력
```claude-code
위 표, 처리 순서, 특수문자 규칙을 API-SPEC "## 변경 검토"에 추가하는 초안을 보여 주세요. "%"와 "_"는 일반 글자로 비교한다고 적으세요.
DATA-MODEL "검토 기록"에는 "검색·필터: DB 구조 변경 없음, 근거, 확인 방법(이전 스크립트 없음), 다시 검토할 조건(검색이 느려지면)"을 추가하세요.
SCREEN-SPEC에는 검색·필터 영역, 결과 수, 빈 결과, URL 복원, 320px 배치를 추가하세요.
TEST-PLAN에는 고정 표본 표와 기대 카드 번호(단독·결합·특수문자·잘못된 값·URL 복원·초기화·320px·사용자 격리)를 추가하세요.
```

- claude-code 입력 (확인한 뒤)
```claude-code
확인했습니다. 문서들을 저장하고 PLAN의 영향 지도와 구현 인계를 갱신하세요. P-32 "완료". "docs: plan search and filters" 메시지로 커밋하세요.
```
