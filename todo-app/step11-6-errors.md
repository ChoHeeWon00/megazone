# STEP 11-6. 오류가 났을 때 — 고장 신고하는 법 (언제든 펴 보기)

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| TEST-PLAN.md | 기대 결과 | 고장 신고서의 **"기대한 결과"**를 여기서 그대로 가져와요. |
| PLAN.md | 지금 하는 P-번호, 마지막 커밋 | **무엇을 바꾼 뒤** 고장 났는지 알려 줘요. |
| API-SPEC.md | 오류 번호(422, 404)의 뜻 | Network 탭에 보인 번호가 **약속된 오류인지** 확인해요. |
| AGENTS.md | 안전 규칙 | AI가 폴더 삭제·보안 설정 끄기를 제안하면 **멈추는 근거**예요. |

---

## 🧸 쉽게 말하면

몸이 아플 때 의사 선생님께 **"아파요"**만 말하면 어디가 아픈지 몰라요.
**"어제 저녁부터, 배 오른쪽이, 밥 먹으면 더 아파요"**라고 말해야 정확히 알 수 있어요. AI도 똑같아요.

```
❌ "안 돼요. 고쳐 주세요."
✅ "제목 '숙제하기'를 저장했는데(한 일),
    카드가 할 일 칸에 생겨야 하는데(기대),
    아무것도 안 생기고 빨간 글자가 떴어요(실제). 오류 글자는 이거예요: ..."
```

## 📋 고장 신고서 (복사해서 쓰세요)

- claude-code 입력
```claude-code
오류가 났습니다. 아직 아무것도 고치지 마세요.
- 하던 작업: [PLAN P-번호, 예: P-16 상태 바꾸기]
- 내가 한 행동: [예: 완료 카드에서 "진행 중으로" 버튼 클릭]
- 기대한 결과: [TEST-PLAN 시나리오 번호와 기대 결과를 그대로]
- 실제 결과: [화면에 보인 것 그대로]
- 오류 글자 원문: [터미널 또는 브라우저 Console의 빨간 글자를 그대로 붙여 넣기]
- 마지막으로 바꾼 것: [예: P-16 구현]
가능한 원인을 가능성 높은 순서로 3개까지 알려 주고, 첫 번째 원인을 확인할 방법을 하나만 제안하세요.
제가 승인하기 전에는 파일을 고치지 마세요.
```

**이 문장을 넣는 이유**

| 문장 | 이유 |
|---|---|
| "아직 아무것도 고치지 마세요" | AI가 원인을 모른 채 여기저기 고치면 더 망가져요 |
| "TEST-PLAN 시나리오 번호" | 기대 결과를 내 기억이 아니라 **문서**에서 가져와요 |
| "오류 글자 원문" | 요약하면 단서가 사라져요. **그대로** 붙여 넣어요 |
| "원인 3개까지, 확인 방법 하나만" | 한 번에 하나씩 확인해야 진짜 원인을 찾아요 |

> ⚠️ 오류 글자에 **비밀번호, 이메일, 내 이름이 들어간 폴더 경로**가 있으면 가리고 붙여 넣어요.

## 🔍 오류 글자는 어디서 찾나?

| 어디 | 무엇이 보이나 | 찾는 법 |
|---|---|---|
| **화면 터미널** (5173) | 화면 만들기 오류 | 화면 서버를 켠 터미널의 빨간 글자 |
| **서버 터미널** (8000) | 서버 오류 (Traceback) | 서버를 켠 터미널의 **맨 아래 줄** |
| **브라우저 Console** (F12) | 화면에서 난 오류 | F12 → Console 탭의 빨간 줄 |
| **브라우저 Network** (F12) | 서버와 주고받은 결과 | F12 → Network → 요청 클릭 → Status |

> 💡 **서버 오류(Traceback)는 맨 아래 줄부터** 읽어요. 맨 아래가 "무슨 일이 일어났는지", 위쪽은 "어떤 길을 지나왔는지"예요.

## 🧯 초보자가 가장 자주 만나는 오류 8가지

| # | 보이는 것 | 쉬운 뜻 | AI에게 할 말 |
|---|---|---|---|
| 1 | `command not found` / `내부 또는 외부 명령이 아닙니다` | 도구가 없거나 터미널을 안 다시 엶 | "도구 설치 여부와 터미널 재시작이 필요한지 확인해 주세요" (11-1) |
| 2 | `Address already in use` / `Port is in use` | 같은 방(포트)을 이미 누가 씀 | "이미 켜진 서버가 있는지 확인하고 어떻게 끄는지 알려 주세요" |
| 3 | `blocked by CORS policy` | 서버가 화면 주소를 허락 안 함 | "CORS 허락 주소와 서버 재시작 여부를 확인해 주세요" (11-4) |
| 4 | `Failed to fetch` / `ERR_CONNECTION_REFUSED` | 서버가 꺼져 있음 | "API 서버가 켜져 있는지 확인해 주세요" |
| 5 | Network Status `422` | 보낸 주문서 양식이 틀림 | "화면이 보낸 내용과 API-SPEC의 필드 이름을 비교해 주세요" |
| 6 | `ModuleNotFoundError` | 서버 부품이 설치 안 됨 | "uv add로 설치했는지, uv run으로 실행했는지 확인해 주세요" |
| 7 | 껐다 켜니 카드가 사라짐 | 저장소 파일 위치가 바뀌거나 메모리에만 저장 | "저장소 파일 경로가 고정되어 있는지 확인해 주세요" |
| 8 | 버튼 글자가 이상함 ("완료으로") | 글자를 자동으로 이어 붙임 | "버튼 글자를 상태마다 따로 정해 주세요" |

## 🔄 함께 고치기 — 고친 뒤에는 꼭

| 순서 | 할 일 | 파일 |
|---|---|---|
| 1 | **같은 행동**을 다시 해서 기대대로 되는지 확인 | (화면) |
| 2 | **원래 되던 기능**도 다시 확인 (회귀) | TEST-PLAN 앞 시나리오 |
| 3 | 오류·원인·수정을 기록 | PLAN 실제 검증 결과 |
| 4 | 원인이 **문서가 틀려서**였다면 문서도 고치기 | 해당 설계 문서 |
| 5 | TEST-PLAN에 없던 상황이었다면 시나리오 추가 | TEST-PLAN |

- claude-code 입력
```claude-code
같은 행동으로 다시 해 보니 기대대로 됩니다. 이 수정 때문에 영향을 받을 수 있는 다른 시나리오를 TEST-PLAN 번호로 알려 주세요.
그리고 함께 고칠 곳을 표로 보여 주세요.
- PLAN.md 실제 검증 결과: 오류, 원인, 수정 내용
- 원인이 문서와 관련 있다면 그 문서와 위치
- TEST-PLAN에 없던 상황이었다면 추가할 시나리오
확인하면 고치고 "fix: [고친 내용]" 메시지로 커밋하세요.
```

## 🆘 그래도 안 되면

| 상황 | 할 일 |
|---|---|
| AI가 같은 수정을 계속 반복 | 멈추고 강사님께. "3번 넘게 같은 오류"는 혼자 붙잡지 않기 |
| 너무 많이 바뀌어서 뭐가 뭔지 모르겠음 | 마지막 커밋으로 되돌리기 (아래) |
| AI가 보안 설정 끄기, 폴더 삭제를 제안 | **하지 말고** 강사님께 (AGENTS 안전 규칙) |

- claude-code 입력 (마지막으로 잘 되던 곳으로 돌아가기)
```claude-code
지금 바뀐 파일 목록을 먼저 보여 주세요. 마지막 커밋 상태로 되돌리면 무엇이 사라지는지 설명하고, 제가 승인하면 되돌려 주세요.
되돌린 뒤 PLAN.md의 해당 작업을 "진행 중"으로 바꾸고, 남은 문제에 되돌린 이유를 적으세요.
```

> 💡 STEP마다 커밋해 둔 이유가 바로 이거예요. **세이브 포인트가 있으면 무섭지 않아요.**
