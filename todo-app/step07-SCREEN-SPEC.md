# STEP 7. SCREEN-SPEC.md — "화면은 어떻게 생겼을까?" (PLAN P-06)

> **SCREEN-SPEC.md** = 사용자가 어떤 화면에서 무엇을 보고, 무엇을 누르고, **잘 안 될 때 무엇이 보이는지**

## 📚 이 단계에서 참고하는 파일

| 참고 파일 | 무엇을 가져오나 | 왜 참고하나 |
|---|---|---|
| PRD.md | 6. 사용자 스토리와 인수 조건, 5. 범위 | 화면에 **무엇을 할 수 있어야 하는지**와 빈 결과·잘못된 입력·실패 때 보일 것을 가져와요. |
| ARCHITECTURE.md | 화면의 책임 ("입력 받기, 보여 주기, 실패 안내") | 화면이 **맡는 일과 안 맡는 일**을 지켜요. (예: 저장은 화면이 하지 않음) |
| DECISIONS.md | D-001, D-002 | 상태 되돌리기 버튼이 필요한지(D-002) 확인해요. |

---

## 🧸 쉽게 말하면

SCREEN-SPEC은 **놀이공원 안내 지도**예요. 어디에 무엇이 있고, 거기서 무엇을 할 수 있고, **문이 닫혔을 땐** 어떻게 되는지 알려 줘요.

---

## ❓ 왜 필요할까?

| 상황 | 화면이 정해져 있지 않으면 |
|---|---|
| 카드가 하나도 없을 때 (빈 결과) | 그냥 빈 화면 → "고장 났나?" |
| 불러오는 중일 때 (처리 중) | 아무 표시 없음 → 버튼을 여러 번 누름 |
| 저장에 실패했을 때 (오류) | 카드가 생긴 것처럼 보였다가 사라짐 |

그래서 화면마다 **정상 / 빈 결과 / 처리 중 / 오류** 네 가지 모습을 정해요.

### 대화 3. 고를 것은 비교받고 내가 고르기

| 골라야 할 것 | 선택지 예 |
|---|---|
| 생성 화면 위치 | 보드 안 입력칸 / 따로 뜨는 창 |
| 카드 표시 정보 | 제목만 / 제목+설명 일부 |
| 상태 변경 방식 | 버튼 / 끌어서 옮기기 |
| 삭제 확인 방식 | 바로 삭제 / "정말 삭제할까요?" 묻기 |
| 좁은 화면 배치 | 열을 가로로 / 세로로 쌓기 |

- claude-code 입력
```claude-code
생성 화면 위치를 정하려고 합니다. "보드 안 입력칸"과 "따로 뜨는 창"을 비교하세요.
저장, 취소, 빈 제목, 저장 실패 때 각각 어떻게 보이는지 설명하고 최종 선택은 기다리세요. 코드는 만들지 마세요.
```

**AI 대답 예시**
> 보드 안 입력칸은 바로 쓸 수 있지만 보드 공간을 차지해요.
> 따로 뜨는 창은 보드가 깔끔하지만, 창을 닫을 때 쓴 내용을 버릴지 정해야 해요.
> 두 방법 모두 빈 제목은 저장하지 않고, 저장 실패 시 쓴 내용을 남기는 게 PRD와 맞아요.

- claude-code 입력 (나머지 네 가지도 같은 방식으로 비교받은 뒤)
```claude-code
제 선택입니다.
- 생성 화면 위치: 따로 뜨는 창 (보드를 깔끔하게 보려고). 저장 실패 때 쓴 내용은 유지
- 카드 표시 정보: 제목 + 설명 두 줄
- 상태 변경 방식: 버튼 (키보드로도 쓰기 쉬워서)
- 삭제 확인 방식: "정말 삭제할까요?" 묻기 (실수 방지)
- 좁은 화면 배치: 세로로 쌓기
SCREEN-SPEC.md의 "대안과 결정" 표에 대안, 사용자 영향, 제 선택, 이유를 적어 주세요.
```
