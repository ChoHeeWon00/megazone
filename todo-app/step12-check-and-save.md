## 🧸 쉽게 말하면

**게임의 세이브 포인트**예요.

```
🎮 세이브 포인트
  - 여기까지는 확실히 깼다!
  - 다음 스테이지에서 실패하면 여기로 돌아온다
```

앱도 **"여기까지는 확실히 동작한다"**는 지점을 남겨 둬요. 이걸 **기준점**이라고 불러요.

### 대화 2b. 발견한 차이를 바로 고치지 말고 나누기 (워크북 Day 9)

시험 중 기대와 다른 점을 찾으면 **바로 고치지 않고 먼저 종류를 나눠요.**

| 분류 | 판정 질문 | 다음 행동 |
|---|---|---|
| **구현 오류** | 정한 조건과 다르게 동작하나? | 11-6 고장 신고서 → 작은 수정 |
| **설계 불일치** | 문서끼리 또는 문서와 PRD가 다른가? | 문서부터 맞추기 (함께 고치기) |
| **범위 안 개선** | 정한 범위 안에서 더 낫게 할 수 있나? | 사람이 승인하면 작게 고치기 |
| **범위 변경** | 새 요구인가? | **이번엔 만들지 않고** PRD "보류 기능"에 기록 |

직접 나눠 보세요.

| 발견한 것 | 분류 |
|---|---|
| 띄어쓰기만 넣었더니 카드가 생겼다 | |
| 삭제 확인 문구가 SCREEN-SPEC과 다르다 | |
| 안내 글자가 작아 잘 안 보인다 | |
| 사람마다 자기 카드만 보고 싶다 | |
| AI가 제목을 추천해 주면 좋겠다 | |

<details>
<summary>👀 예시 답 보기</summary>

구현 오류 / 설계 불일치(어느 문서가 기준인지 먼저 확인) / 범위 안 개선 / **범위 변경 → 보류 기능** / 범위 변경이지만 D-001(AI 기능 없음)과 충돌 → 제외

- claude-code 입력

```claude-code
[발견 사항 붙여 넣기]
```

#### 범위 변경은 "보류 기능"으로 남기기

범위 변경은 **거절이 아니라 보관**이에요. 다음 변경(STEP 13)의 씨앗이 돼요.

- claude-code 입력
```claude-code
"사람마다 자기 카드만 보고 싶다"를 PRD.md "## 보류 기능"에 아래 6항목으로 기록하세요.
1. 사용자가 겪는 문제와 원하는 결과 / 2. 지금 PRD에 없는 이유 / 3. 영향 받는 흐름과 규칙
4. 화면·API·데이터·보안 영향 / 5. 지금 추가하지 않았을 때 영향 / 6. 다음에 먼저 정할 질문
이번 구현에는 넣지 마세요.
```

## 🎉 축하해요!

아무것도 없는 폴더에서 시작해서 **할 일 웹앱**을 완성했어요.

```
STEP 1~5   무엇을 만들지 정했고        README → AGENTS → DECISIONS → PLAN → PRD
STEP 6~10  어떻게 만들지 정했고        ARCHITECTURE → SCREEN → DATA → API → TEST
STEP 11    AI가 만들고 내가 확인했고    도구 → 화면 → 서버 → 연결 → 기능 → 다시 켜기
STEP 12    세이브 포인트를 남겼어요     전체 시험 → 기준점 → 태그
```

### 가장 중요한 세 가지

1. **대화는 사라지고 파일은 남는다.** → 정한 건 파일에!
2. **AI가 "다 했어요"는 증거가 아니다.** → 내 눈으로 확인!
3. **결정은 내가, 코드는 AI가.** → 모르면 "설명해 줘"! 하나를 바꾸면 **함께 고치기**!

## ➡️ 그다음은? → STEP 13

기준점에서 새 기능을 추가해요. **STEP 13~15**에서 로그인, 우선순위·마감일, 검색·필터를 차례로 붙이고, **STEP 16~18**에서 디버깅, 자동 테스트, 배포 준비까지 해요.
먼저 `step13-0-change-cycle.md`에서 **기능 추가의 공통 순서**를 읽어요.

```
새 기능 아이디어
 → PLAN에 새 작업 추가                (무엇을 할지)
 → PRD에 "변경 제안"                   (무슨 문제를 해결하나?)
 → DECISIONS에 결정                    (왜 그렇게 하나?)
 → 설계 문서 고치기                    (SCREEN → DATA → API)
 → TEST-PLAN에 시나리오 추가            (무엇을 보면 통과?)
 → 새 대화에서 하나씩 만들기            (11-5처럼)
 → 확인하고 새 기준점                   (STEP 12처럼)
```
